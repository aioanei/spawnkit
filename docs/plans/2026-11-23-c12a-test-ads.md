# C12a Test Ads with Real Counts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first half of C12 ([#77](https://github.com/aioanei/spawnkit/issues/77), [design §7](../design/2026-11-22-title-screens-presets-accounts-ads.md#7-c12--test-ads-and-test-purchases-with-real-counts)):
creators turn on test ads, Arcade plays really count views and clicks, and a statistics view shows them with revenue
honestly at $0.00. C12b adds test purchases.

**Architecture:**
- **Settings in the project.** `Project.ads` (`AdSettings`: banner on the start scene, interstitial between scenes and
  how many scene changes apart). Workspace schema 3 migrates older files with ads off. `set_ads` is a catalog
  operation, changed from the Release Manager's Ads section.
- **Player.** `AdSchedule` decides, from the play session's scene changes, when the banner shows and when an
  interstitial is due: never on the first scene change, so never before the first play. `AdHost` shows a placement and
  returns an explicit result; `TestAdHost` draws a labelled "TEST AD — SpawnKit" panel. Nothing calls an ad SDK or a
  third party. An optional `AdReporter` receives views and clicks; the builder passes none, so previews never count.
- **Arcade.** The web player reports to `POST /api/games/{slug}/ad-events` in batches with a random play-session ID
  and per-event numbers: no personal data. The server deduplicates by session and number, rate-limits by address and
  aggregates per game and UTC day. Exported games played offline show test ads without reporting.
- **Statistics.** `GET /api/games/{slug}/ad-stats` for the owner only: views, clicks and click-through rate per day,
  and revenue fixed at zero. The Release Manager's My games opens a statistics view with "$0.00 — test ads earn
  nothing" and an optional What if line labelled "estimate, not earnings".

## Tasks

### Task 1: Settings
- `AdSettings`, `Project.ads`, `SetAds` and `set_ads`; schema 3 with migration. Tests: defaults off, round trip,
  migration from schema 1 and 2, limits, undo.

### Task 2: Player
- `AdSchedule`, `AdHost`, `TestAdHost`, `AdReporter`, wired into `GamePlayer` and builder Play. Tests: banner only on
  the start scene; interstitial every N changes and never on the first; closing and clicking; builder play reports
  nothing.

### Task 3: Server
- `AdEvents` tables (schema 2 migration), the events route and owner-only statistics. Tests: once per session and
  number, aggregation by day, rate limit, unknown games, owner-only access, revenue zero.

### Task 4: Web player and builder statistics
- The web player's reporter; `AccountClient.adStats`; the statistics view in both layouts; parity case for `set_ads`;
  UI tests and screenshots; docs and `PROGRESS.md`.
