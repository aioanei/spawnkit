# C15b Images in Projects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The second half of C15 ([#89](https://github.com/aioanei/spawnkit/issues/89)): creators import PNG images,
use them as sprites (the Image palette piece), keep pixel art crisp, and the images travel with saves, exports and the
Arcade. Decision: [ADR-0012](../adr/0012-images-in-projects.md).

## Tasks

### Task 1: Images in the project model (`core/editing`)
- `ImageAsset`, `Project.images`, `ImageFiles` (PNG header, SHA-256, limits), `AddImage` / `RenameImage` /
  `RemoveImage` with catalog entries, `ValueKind.Text.asset` checks, schema 2 with the schema 1 migration, raised
  file and package limits.
- Tests: migration from a schema 1 file; round trip with an image; damaged data, wrong hash, too large and non-PNG
  refused; removing a used image refused; duplicate refused; undo.

### Task 2: Drawing images
- `Sprite2D.pixelated`, `DrawItem.Sprite.pixelated`; `RuntimeCanvas` draws without filtering when pixelated;
  `rememberImages(project)` decodes once per hash for the builder, Play, exported players and the web player.
- Tests: render-list carries pixelated; a canvas screenshot test shows the image's pixels.

### Task 3: Builder
- Import on Android (system picker) and desktop (file dialog); an Images list in the Add tab with Use, Rename and
  Remove; the Image piece; an image picker for sprite assets in the inspector.
- Parity cases for the three operations; `ImagesUiTest` in both layouts.

### Task 4: Evidence
- Image round trip through save, export and an Arcade upload and download (server test).
- Android emulator: import a logo, put it on the home screen, play it; screenshots. Docs and `PROGRESS.md`.
